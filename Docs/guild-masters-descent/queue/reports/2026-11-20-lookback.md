In ten days the queue took 129 items to done, 15 sit in Blocked, and nothing the user saw was
sent back as wrong. The runner itself held up: two takedowns in ten days (#33 on 11 Nov and #88
on 14 Nov, both a worker whose turn ended without its finished mark), each resumed cleanly on

## What worked

- **Slicing big items.** An [L] item cut into slices, each test-author → auditor → writer →
  suite, kept most agents under the bound and finished (#68, #72, #90). The test-auditor found
  real holes nearly every time it ran (#37, #55, #58, #69, #90).
- **Alignment before the first review** on a contract-heavy PRD let one review round be the
  only round (#33, #34).
- **Fresh instances with a hand-off brief** instead of a third resume were cheap every time
  (60–90k against the 250k+ the first run reached: #36, #100, #105).
- **The standing approval and standing yes** kept the queue full: proposals queued their own
  rows (#99, #110, #125, #140, #146, #164) and approved work reached main without the user
  waiting on a merge.
- **Fixes already landed from earlier notes:** a soft question no longer parks its item
  (`--going-ahead`; the last complaint is #116 on 16 Nov), and the user's words now live in the
  item's brief, which a stage note cannot overwrite (#113's complaint).

## What did not

1. **There is still no test command for the project.** About 30 worker notes, from #33 on
   11 Nov to #163 today, say the same thing: the manifest has no `testing.command`, so every
   worker rebuilds the batch-mode Unity line or copies a `runtests.sh` out of an old scratchpad
   (once it copied a 0-byte file, #104). The facts they keep rediscovering: the full Unity app
   path, not the new CLI (#46); an absolute `-testResults` path (#36); never `-nographics`, or
   DeathDissolveViewTests fail and GPU tests go inconclusive (#67, #78, #133); exit code 2 means
   inconclusives, so read the XML totals (#124, #153, #155). `project.json` belongs to
   `/set-project`, so no worker can add it.
2. **The test-author has no compiler, so its fixtures break only at first run.** Twelve notes
   (#32, #57, #65, #70, #72, #76, #77, #85, #90, #129, #153, #158) name a fixture that failed for
   a reason a compile or a single run would have shown: NUnit 3.5 overloads that don't exist,
   `GetInstanceID` and `preloadAudioData` being errors in Unity 6000.6, a Cook or Porter as a
   monster (the engine forbids it), a duplicate `[Test]`. Each one cost a resume or a fresh
   dispatch after the writer's run. Neither the test-author's nor the auditor's instructions
   carry any of these project facts today.
3. **Writers and test-authors still pass 250k.** Eighteen notes report it. The worst were all
   items whose size tag understated them: #116 (an [S] that touched a shared measurement: 40
   files, four writers, one at 417k), #118 (two writers at 305k and 428k before an opus writer
   proved by arithmetic that the content could not fit), #121 (360k on 23 requirements in one
   dispatch), #129 (380k for the group that owned every shared fixture), #151 (356k). The notes
   agree on the cut: split an M or L PRD's test stage by requirement group, and put
   "rewrite the existing fixtures" in its own dispatch.
4. **The Queue page's first publish in a fresh worker is refused.** Twelve notes (#30, #39,
   #44, #49, #51, #60, #61, #77, #111, #115, #135, #149). The command's fix — Read the saved
   copy, then publish unchanged — sometimes still needs a third send (#135, #149): a Read of
   only a few lines does not count.
5. **[look] plans guess measurements.** #118 (font not measured), #136 (sweep rules not run),
   #157 (one formation measured, not every one), #159 (reference aspect only, 27 false
   failures). The command now asks for measured fonts and art; it does not yet ask for the test
   canvas aspect or every dive formation.

## Proposals

PROPOSAL: Add the project's test command to `project.json` through `/set-project` (the user's command) — Unity at its full app path, `-batchmode -projectPath src/guildmasters-descent -runTests -testPlatform EditMode -testResults <absolute xml>`, no `-nographics`, read pass/fail from the XML totals and not the exit code — ends the most repeated cost in the queue.

PROPOSAL: A project test script in the game repo (`run-tests.sh`: the line above under a time limit, printing passed / failed / inconclusive from the XML, optional `-testFilter`), so the manifest's command is one short call and writers, cleaners and the main loop share it [look] [S].

PROPOSAL: Give forge-test-author and forge-test-auditor a short "this project" block, via `/agent-creator` or a per-project notes file they read: NUnit 3.5 (no `SetArgDisplayNames`, check an `Assert` overload is used elsewhere in the repo first), Unity 6000.6 errors (`GetInstanceID`, `preloadAudioData`), monsters are only the six combat types, the Fighter's flurry needs a weapon, fully qualified names for Core types that clash with `UnityEngine.UI`.

PROPOSAL: Add a compile check after every forge-test-author hand-back — the main loop runs the suite once (it is expected red, but it must compile and its fixtures must reach their asserts) and hands any fixture failures back before the auditor runs, instead of after the writer.

PROPOSAL: In `/forge-queue`, split the test stage of any [prd] M or L item by requirement group from the first dispatch, with "rewrite the existing fixtures this change breaks" as its own dispatch; and re-size an item [S]→[M]/[L] at triage when it changes a shared measurement or a type every fixture uses.

PROPOSAL: In `/forge-queue`'s publish step, say the Read of the saved copy must be the whole file (or call `Artifact` `read` on the url), since a partial Read still gets the resend refused.

PROPOSAL: In the [look] Plan brief, add: measure at the test canvas's aspect as well as the reference one, and measure every dive formation the screen can show, not one fixture.

PROPOSAL: A mastermind tidy pass over Blocked as its own job, even under the standing yes: for each open question, check the later notes and the built code named above (#3, #25, #27, #48, #59) and answer from the doc that now says it, or mark it overtaken.

PROPOSAL: Under the standing yes, the mastermind holds a proposed build row behind an open decide: row or blocked item it depends on (queue it only once that is answered), instead of queuing it to park at once.
